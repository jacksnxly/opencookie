<Aside type="note" title="Nuxt 4">
This guide uses the current Nuxt 4 starter. Nuxt 3 reached end of life on 31 July 2026 and no longer receives bug fixes or security patches, so the adapter now supports Nuxt 4 only. See the [Nuxt roadmap](https://nuxt.com/docs/4.x/community/roadmap), accessed 2026-09-23.
</Aside>

## Verified fresh-app workflow

Create an empty directory, enter it, then run these exact commands in order. pnpm 11 rejects unreviewed dependency build scripts, so create the narrow allowlist after scaffolding and before installing. The file permits only Nuxt's required `esbuild` setup.

- Scaffold: `pnpm dlx create-nuxt@3.37.0 . --template minimal --force --packageManager pnpm --no-install --gitInit=false`
- Approve builds: `node --input-type=module --eval 'import { writeFile } from "node:fs/promises"; await writeFile("pnpm-workspace.yaml", Buffer.from("YWxsb3dCdWlsZHM6CiAgImVzYnVpbGQiOiB0cnVlCg==", "base64"), { flag: "wx" });'`
- Install: `pnpm install --no-frozen-lockfile`
- Initialize: `npx --yes opencookie@0.4.1 init --yes`
- Build: `pnpm build`
- Serve: `node .output/server/index.mjs`

Set `HOST=127.0.0.1` and `PORT=4173` in the environment when you run that serve command. Nuxt otherwise listens on port 3000, which is the one address in this guide set that would differ from every other framework page. Then open `http://127.0.0.1:4173/` to inspect the production build and its initialized banner.

Observed output: on 2026-09-23 the packed fresh-app run built the Nuxt 4 app, the production build exited 0, and the Node server answered. In Chromium the banner rendered and a decision persisted across a navigation, and a second initialization changed nothing.

<Aside type="caution" title="Blocked scripts in the document head">
If you declare a blocked resource in `app.head` and your server gives each response its own CSP nonce, Nuxt 4 inserts the tag a second time on hydration: browsers hide a nonce from scripts, so Nuxt cannot match the server-rendered tag. The resource would then run twice after consent. Render such tags on the server only, with `useHead` inside `if (import.meta.server)`, as this repository's Nuxt fixture does. See [unjs/unhead#136](https://github.com/unjs/unhead/issues/136), accessed 2026-09-23.
</Aside>

The supported range is `>=4.5.2 <5.0.0`. The store module is registered as `~~/opencookie-store`, the project root, because Nuxt 4 resolves `~` to the `app/` directory.
