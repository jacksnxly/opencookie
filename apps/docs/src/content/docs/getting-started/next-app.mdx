## Verified fresh-app workflow

Create an empty directory, enter it, then run these exact commands in order. Keep the import alias quoted so the shell does not expand `*` before the scaffold receives it.

- Scaffold: `pnpm dlx create-next-app@16.4.6 . --ts --no-linter --no-tailwind --app --empty --no-src-dir --no-react-compiler --import-alias '@/*' --no-agents-md --disable-git --skip-install --yes`
- Install: `pnpm install --no-frozen-lockfile`
- Initialize: `npx --yes opencookie@0.4.1 init --yes`
- Build: `pnpm build`
- Serve: `pnpm start --hostname 127.0.0.1 --port 4173`

Open `http://127.0.0.1:4173/` to inspect the production build and its initialized banner.

Observed output: Next compiled successfully, generated the root route, the production build exited 0, and the production server returned HTTP 200.

## Browser-verified result

This exact production workflow was exercised from a clean storage state in a real browser. Before consent, `opencookie-demo.js` had zero requests and zero executions. Accept all persisted across a new navigation. Analytics was then denied with Save choices, consent was withdrawn, and a final navigation again produced zero demo requests and executions.

<Steps>
1. Run the pinned unattended initializer at the Next project root.
   The initializer installs `@opencookie-dev/core`, `@opencookie-dev/next`, and `@opencookie-dev/vanilla`.
2. Keep the root layout as a Server Component. The initializer generates one narrow client boundary and wraps `{children}` with it.

   <RunnableSample id="next-app" title="app/opencookie-provider.tsx" />

3. Render that boundary around route content and place the preferences host beside the content slot so navigation cannot remove it.
</Steps>

`@opencookie-dev/next` is a closed wrapper over `@opencookie-dev/react`; it does not duplicate consent logic. The module is marked for client use while the core client itself still has a deterministic server snapshot.

Read the [SSR recipe](/recipes/ssr-hydration-cls/) before adding dynamic rendering or streamed layouts.

If the root layout already has content, add
`import { OpenCookieRoot } from "./opencookie-provider";` by hand and place the
layout's content inside the `body` element. Wrap the content, `{children}`
included, in the `OpenCookieRoot` component. Run `opencookie init --yes` again
after making that change; the initializer then generates the provider and keeps
the layout unchanged.
